TLS — the path that was needed, not the path that is convenient

There is no Route 53 zone and no ACM certificate in the account, so a DNS-validated certificate from a public CA is impossible. Two paths are implemented behind a cert_mode variable:

  • self-signed (default): scripts/tls/generate-selfsigned.sh writes a key to a gitignored

path and prints the aws acm import-certificate command, so the key never enters state.

  • http01: no ACM cert; cert-manager solves HTTP-01 against the ALB hostname through sslip.io

and TLS terminates at Traefik.

The gate caught two real violations, which is the whole point of a gate

Traefik's Middleware CRD was wrong in two ways, and kubeconform on the rendered chart output caught both — the raw template cannot be validated because {{- if }} is not YAML:

Summary: 15 resources found in 1 file - Valid: 15, Invalid: 0, Errors: 0, Skipped: 0

1. redirectScheme.port: 443 — the CRD types the port as a string, so the API server would have rejected it. 2. sourceCriterion was nested at spec level; the schema only allows it inside rateLimit. Fixed by keying on the client IP instead of X-Forwarded-For, which is the correct control anyway: the header is attacker-controlled on a request that never reached the ALB.

Both would have been discovered at helm install on a real cluster, which is exactly the class of failure a local gate should catch first.

ACME on a DaemonSet is impossible, and that shaped the design

The chart refuses to render a DaemonSet with any --certificatesresolvers.*.acme.* argument: ACME writes acme.json, and a DaemonSet runs one pod per node, each with its own copy, so renewals would race and clobber. The HTTP-01 challenge therefore runs in cert-manager (single Deployment, account key in a Secret) and Traefik reads the issued certificate from that Secret. Declaring the resolver only by name, and not at all in self-signed mode.
